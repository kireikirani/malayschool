# Rencana: Sistem Permohonan Keluar Asrama (Borang / Semak / Guard / Admin)

Membangun replikasi 4-tab prototype Canva ke dalam arsitektur `malayschool` yang sudah ada (Next.js 16 + Drizzle MySQL + better-auth), mengikuti pola modul asrama yang sudah ada persis.

## Keputusan (dari klarifikasi)
- **Borang** = publik tanpa login; validasi Nama + No. Waris terhadap tabel `asramaPelajar`
- **Guard** = dijalankan oleh **warden (role `teacher`)** yang sedang login → route `/guard`, gating `requireAdminOrTeacher`. **Tidak ada perubahan enum role.**
- **Admin** = modul baru di `/admin/asrama-permohonan` dalam admin shell
- **Checkout** catat: nama pengambil + no. pendaftaran (plat) + tarikh
- **Admin scope**: approve/tolak+catatan, buat MC/Sakit, edit/padam, statistik+export

## 1. Database — 1 tabel baru

**`db/schema/asrama-permohonan.schema.ts`** (mengikuti konvensi `asrama-pelajar.schema.ts`):

```
asrama_permohonan
  id              int autoincrement PK
  pelajarId       int (FK → asrama_pelajar.id, onDelete cascade)
  namaPelajar     varchar(200)        -- snapshot nama saat submit
  tingkatan       varchar(10)         -- snapshot
  dorm            varchar(100)        -- snapshot
  jenis           enum ['pulang_bermalam','outing','mc_sakit']
  tarikhKeluar    date
  tarikhPulang    date null           -- null untuk MC
  sebab           text
  status          enum ['menunggu','diluluskan','ditolak','mc']  default 'menunggu'
  noWarisPengirim varchar(20)         -- pengecam waris saat submit (verifikasi)
  -- kelulusan
  diluluskanOleh  varchar(200) null   -- nama approver (snapshot dari session)
  approverUserId  varchar(36) null    -- FK → user.id (audit), onDelete set null
  tarikhKelulusan timestamp null
  catatan         text null
  -- checkout (guard)
  pengambil       varchar(200) null
  noPendaftaran   varchar(20) null    -- plat kenderaan
  guardUserId     varchar(36) null    -- FK → user.id, onDelete set null
  guardNama       varchar(200) null   -- snapshot nama guard
  tarikhDiambil   timestamp null
  -- standard
  createdAt, updatedAt
  indexes: status_idx, jenis_idx, pelajar_id_idx, tarikh_keluar_idx
```

Daftarkan di `db/schema/index.ts`. Tambah `asramaPermohonanRelations` di `relations.ts` (→ asramaPelajar, user x2).

**Validasi**: `lib/validations/asrama-permohonan.schema.ts`
- `createPermohonanSchema` (publik): nama, noWaris, jenis, tarikhKeluar, tarikhPulang?, sebab
- `approvePermohonanSchema`: status ('diluluskan'|'ditolak'|'mc'), catatan?
- `checkoutSchema`: pengambil, noPendaftaran
- `mcSchema` (admin buat MC): pelajarId, tarikhKeluar, sebab
- `permohonanQuerySchema`: status, jenis, q, pagination

**Migrasi**: jalankan `npm run db:generate` → review `drizzle/0008_*.sql` → `npm run db:push`.
⚠️ **CATATAN PENTING**: disk sempat penuh (ENOSPC saat subagent jalan). Sebelum `db:generate`, saya akan pastikan space cukup. Kalau masih penuh, saya berhenti dan laporkan.

## 2. API Routes (mengikuti pola `requireAdmin`/`parseBody`/`handleApiError`)

### A. Publik (tanpa auth)
- **`app/api/permohonan/route.ts`**
  - `POST` → buat permohonan. **Validasi identitas**: cari `asramaPelajar` WHERE nama ILIKE input AND noWaris = input. Kalau tidak match → `ApiError("Maklumat pelajar tidak sah", 400)`. Rate-limit per IP (`rateLimit(ip:permohonan, 5, 60_000)`). Jenis `mc_sakit` DITOLAK di endpoint publik (hanya admin).
  - `GET` → semak status. Query by `noWaris` (atau `pelajarId`) → return list permohonan pelajar itu saja. Tidak exfiltrate data pelajar lain.

### B. Guard (`requireAdminOrTeacher`)
- **`app/api/permohonan/guard/route.ts`**
  - `GET` → list permohonan `status IN ('diluluskan','mc')` (counter atas), search by nama/tingkatan (search-only, tidak dump semua — default 0 row sampai ada query `q`).
  - `GET ?id=` → detail 1 permohonan
- **`app/api/permohonan/guard/[id]/checkout/route.ts`**
  - `POST` → set `pengambil`, `noPendaftaran`, `guardUserId` (dari session), `guardNama`, `tarikhDiambil=now`. Cegah double-checkout.

### C. Admin (`requireAdmin`)
- **`app/api/admin/asrama-permohonan/route.ts`** — GET (list+filter+stats), POST (buat MC atas nama pelajar)
- **`app/api/admin/asrama-permohonan/[id]/route.ts`** — GET, PATCH (edit), DELETE
- **`app/api/admin/asrama-permohonan/[id]/approve/route.ts`** — POST (approve/tolak + catatan, set `diluluskanOleh`, `approverUserId`, `tarikhKelulusan`)
- **`app/api/admin/asrama-permohonan/export/route.ts`** — GET → CSV/xlsx (pakai dep `xlsx` yang sudah ada)

## 3. Frontend — 4 area

### A. Borang (publik) — `app/(public)/asrama/permohonan/page.tsx` + client component
UI pilih jenis (Pulang Bermalam / Outing), lalu form: Nama Pelajar, No. Waris, Tarikh Keluar, Tarikh Pulang, Sebab. Submit POST ke `/api/permohonan`. Notis "3 hari sebelum". Toast sukses → redirect ke Semak Status.

### B. Semak Status (publik) — `app/(public)/asrama/permohonan/semak/page.tsx` + client
Input No. Waris (atau pilih dari sesi) → GET `/api/permohonan?noWaris=` → card list dengan filter chip (Semua/Menunggu/Diluluskan/MC/Ditolak). Replikasi card detail dari prototype (jenis, tarikh, sebab, status badge, kelulusan+catatan, rekod pengambilan).

### C. Guard — `app/guard/layout.tsx` (gating `requireAdminOrTeacher` server-side, redirect `/login`) + `app/guard/page.tsx` (client)
**Search-only**: input cari nama → baru query. Tidak load semua saat buka. Counter atas (Diluluskan/MC count). Card pelajar → tombol "Rekod Pengambilan" → dialog (Nama Pengambil + No. Pendaftaran) → POST checkout. Tampilan "✅ TELAH DIAMBIL" jika sudah.

### D. Admin — `app/admin/asrama-permohonan/page.tsx` (server fetch) + client component
`DataTable` (pola `asrama-pelajar`) + filter status/jenis/tingkatan + search. Kolom: pelajar, jenis, tarikh, status (badge). Aksi dropdown: Lihat detail, Approve (dialog catatan), Edit, Padam. Tombol "+ Buat MC/Sakit". Card statistik atas (Menunggu/Diluluskan/MC/Ditolak) + tombol Export.
Tambah nav item baru di grup "Asrama" `components/app-shared.tsx`: `{ title: "Permohonan Keluar", path: "/admin/asrama-permohonan", icon: <ClipboardList/> }`.
